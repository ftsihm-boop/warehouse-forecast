# Система интеллектуального управления складскими запасами

Прогноз спроса и автоматический расчёт закупки. Менеджер загружает выгрузку
продаж из кассы или 1С — получает список «что, сколько и когда заказать».

## Быстрый старт

```bash
pip install -r requirements.txt

# 1. сгенерировать тестовые данные (чистые и специально испорченные)
python scripts/make_synthetic.py --days 730 --out data/clean.csv
python scripts/make_synthetic.py --days 730 --messy --header-1c --out data/messy.xlsx

# 2. обучить глобальную модель
python -m src.train --data data/clean.csv --out models/global

# 3. прогнать весь пайплайн от очистки до бэктеста
python scripts/run_demo.py --data data/messy.xlsx

# 4. поднять API для веб-интерфейса
uvicorn api.main:app --reload --port 8000
```

Тесты: `pytest -q` или `python tests/test_pipeline.py` (работает без pytest).

### Гибридная схема (вариант C)

Режим выбирается **по каждому товару отдельно**, а не по файлу целиком:

| История | Режим | Что происходит |
|---|---|---|
| ≥ 180 дней | `fine_tune` | Глобальная модель дообучается на данных пользователя (`init_model` в CatBoost) |
| 60–179 дней | `global` | Предобученная модель как есть |
| 14–59 дней | `stats` | Скользящее среднее + перцентиль, в интерфейсе честная плашка |
| < 14 дней | `reject` | Отказ с объяснением |

### Два решения, без которых гибрид не работает

**1. Модель не знает, что за товар она предсказывает.**
В признаках нет `sku`, `item_id`, `category` — только форма ряда. Поэтому
модель, обученная на дисках 1С, применима к молоку.

**2. Предсказываем множитель, а не штуки.**

```
target = (сумма продаж за горизонт) / (среднее за 28 дней × горизонт)
```

Товар с 5 шт/день и товар с 500 шт/день после нормировки для модели
одинаковы. Обратно умножаем при выдаче. Без этого перенос на чужие данные
не летит: модель выучит масштабы обучающей выборки.

**Бонус: целевая — сумма за горизонт, а не значение конкретного дня.**
Точно предсказать, сколько молока продадут 14 ноября, невозможно;
«за следующие 30 дней уйдёт 480–540 литров» — реально, и именно это нужно
для расчёта заказа. Дневная раскладка для графика делается отдельно,
по профилю дня недели (`forecast_curve`).

## Очистка данных: пять слоёв

**Слой 1 — структура.** Синонимы колонок (`Номенклатура`, `item_cnt_day`,
`Продано, шт.`), поиск строки шапки в первых 20 строках (выгрузки 1С кладут
сверху 3–5 служебных строк — это и есть типовая причина ошибки «колонки не
найдены»), выбор листа с наибольшим числом распознанных колонок.

**Слой 2 — типы.** Даты: Excel serial (`45890`), ISO, `31.12.2025`, `31/12/25`,
«31 декабря 2025». Числа: `1 234,56`, `1,234.56`, неразрывный пробел,
`12 шт`, `—`, `н/д`.

**Слой 3 — логика.** Возвраты (отрицательные продажи) → 0 с флагом.
Дубли «дата+товар» → суммируются. Похожие наименования («Молоко (1 литр)» и
«Молоко(1 л)») → склеиваются. Пропущенные даты → дозаполняются нулями:
для временного ряда пропуск строки означает «продали 0», а не «нет данных».
Выбросы → винзоризация по MAD, не удаление.

**Слой 4 — цензурированный спрос.** День, когда продажи = 0 **и** остаток = 0,
это не «спроса не было», а дефицит: спрос был, товара не было. Если скормить
такие дни модели как честные нули, она научится систематически занижать спрос —
и система начнёт усугублять out-of-stock вместо того чтобы его лечить.
Такие дни помечаются и исключаются из расчёта статистик.

**Слой 5 — отчёт.** Машиночитаемый (`report.to_dict()` → JSON для интерфейса)
и текстовый (`report.to_text()` → кнопка «скачать лог», скриншот в курсовую).

## Страховой запас: квантили вместо коэффициента 1,65

Учебная формула `SS = 1.65 × σ × √L` предполагает нормальное распределение
спроса, которого у штучных товаров нет и близко: много нулей, редкие всплески,
асимметрия. Вместо этого обучаются две модели — на квантиль 0.5 и 0.9 —
и страховой запас берётся как их разность:

```
SS  = q90(спрос за L) − q50(спрос за L)
ROP = q50(спрос за L) + SS
Q   = q90(спрос за L + R) − остаток − товар в пути
```

Распределение берётся из самих данных, а не из предположения о его форме.
На защите это отдельный сильный пункт.

## Метрики: WAPE, а не только MAPE

`MAPE = mean(|y − ŷ| / y)` взрывается при y близком к нулю: день с продажей
1 шт и прогнозом 3 шт даёт вклад 200%. У сезонных товаров (персики зимой)
таких дней много. `WAPE = Σ|y − ŷ| / Σy` устойчив к нулям и читается как
«ошиблись на N% от оборота». Считаем обе: MAPE — потому что он в SMART-цели,
WAPE — потому что он честный.

## Результаты на синтетических данных (8 товаров, 730 дней)

Модель обучена через sklearn-фолбэк; с CatBoost цифры будут лучше.

| Модель | WAPE, % | MAPE, % | MAE |
|---|---|---|---|
| **Градиентный бустинг (наш)** | **9.38** | **14.93** | 59.3 |
| Скользящее среднее 28 дней | 11.33 | 16.37 | 72.3 |
| Наивный (прошлый период) | 11.42 | 16.45 | 72.9 |
| Сезонный наивный (год назад) | 11.98 | 14.83 | 76.5 |

Бэктест политики закупки за 180 дней:

| Показатель | Ручное планирование | ML-прогноз |
|---|---|---|
| Средний остаток, ₽ | 81 162 | 62 096 (−23,5%) |
| Упущенная выручка, ₽ | 6 010 | 2 320 (−61,4%) |
| Затраты на хранение, ₽ | 14 010 | 10 717 |

Экономические допущения (закупочная цена, наценка, ставка хранения) —
параметры класса `Economics`, а не зашитые числа. На защите их нужно
называть явно.

| POST | `/upload` | файл → `session_id` + отчёт об очистке |
